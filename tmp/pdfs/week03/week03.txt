What is IPC?
Textbook Definition
Communication between processes over the network, or inter- process
communication (IPC), is at the heart of distributed systems — it’s what
makes distributed systems distributed
The exchange of data between two or more separate, independent
processes or threads.
Each process is an island with its own address space, code, and data.
The Operating System (OS) provides the facilities to bridge these
islands.
The bridge can be considered as the Application programming
interface(API) which allows for high level IPC programming.
The API defines the set of rules that determine how data is
processed and formatted throughout the communication.

Communication Styles
Direct communication: the sender communicates directly with the
intended receiver. The sender must know the identity or address of
the destination process or service before communication can occur.
Indirect communication: processes exchange messages through an
intermediary, such as a message broker, message queue, or event bus.
Sender and receiver don’t need to be online at the same time.

Failure detection
Indefinite Blocking: A process might ”hang” forever if a network link fails during
a blocking call.
Timeout: Returns a special error code if a process blocks for too long, allowing for
recovery logic.
Deadlock: Issuing blocking operations in the wrong sequence (e.g., P1 waiting for
P2, and P2 waiting for P1).

Message Representation and Transfer
Applications communicate using high-level data structures, while computer
networks only transmit binary data (bits and bytes).
High level data structures: Objects, Records, Arrays, JSON
documents, Classes and Structures
The Representation Problem: Different architectures represent
data differently.
- Intel x86 vs AMD64 vs ARM (Apple Silicon, Raspberry Pi)
The Challenge of Heterogeneity: communicating machines may
differ in many ways.
- Byte-ordering: Big-endian (UNIX SPARC) vs. Little-endian (Wintel).
- Types: Differences in how characters (ASCII vs. Unicode) are encoded.
- Numeric Formats: Integer sizes; Floating-point representation; Signed
vs unsigned integers.

===== PAGE 20 =====
The Transport Layer in IPC
The Transport Layer provides end-to-end communication between
applications running on different hosts.
This layer creates reliable communication channel on top of IP.
Port numbers address specific processes or services on a host.
Example of default ports:
HTTP: 80
HTTPS: 443
MySQL: 3306
Ballerina Service: 8080
Communication can only happen if processes in IPC have an agreed
protocol. TCP vs UDP
TCP: Connection-oriented, reliable byte stream.
UDP: Connectionless, ”best-effort” datagram service (fast but
unreliable)

How TCP Achieves Reliable Messaging?
Segmentation: Large messages are divided into smaller TCP
segments before transmission.
Sequence Numbers: Every TCP segment receives a unique
sequence number.
Acknowledgements: Connection establishment uses three-way
handshake.
Retransmission:If no acknowledgement arrives before a timeout
expires.

Takeaways
IPC enables cooperation between independent processes.
Message passing is the foundation of distributed systems.

* Synchronous or asynchronous
* Unicast or multicast

Modern IPC technologies include:
* TCP/IP
